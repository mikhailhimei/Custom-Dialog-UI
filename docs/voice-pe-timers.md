# Таймеры на кольце Home Assistant Voice PE

Обновите Custom-Dialog-UI и перезапустите Home Assistant. Интеграция создаёт
датчик `sensor.dialog_custom_ui_timers`. Его атрибут `payload` содержит JSON
последнего оставшегося таймера каждого устройства и обновляется раз в секунду.
Таймер выбирается по времени создания, а не по UUID или времени до окончания.
Время создания сохраняется вместе с таймером в JSON.

Обновите прошивку Voice PE из ветки `dev` репозитория
`mikhailhimei/home-assistant-voice-pe`. По умолчанию прошивка читает этот датчик
через API Home Assistant. Интеграция сопоставляет `deviceId` таймера с именем
ESPHome через реестр устройств, поэтому вручную указывать ID обычно не нужно.
Подключение ESPHome в Home Assistant должно быть доступно.

Если датчик получил другое имя (например, при нескольких экземплярах интеграции),
укажите его в YAML колонки:

```yaml
substitutions:
  dialog_timer_entity: sensor.dialog_custom_ui_timers_2
```

Если таймер использует нестандартный идентификатор устройства, можно указать
точное значение `deviceId` из JSON таймера:

```yaml
substitutions:
  dialog_timer_device_id: "идентификатор устройства"
```

Во время ожидания команды кольцо показывает обычную анимацию помощника.
В свободном состоянии оно показывает долю оставшегося времени таймера.
Пауза замораживает прогресс. При удалении или окончании последнего таймера
отображается предыдущий оставшийся; если их нет, кольцо возвращается в обычное
состояние. Через 15 секунд без обновлений датчика индикация внешнего таймера
сбрасывается. Штатные таймеры ESPHome работают, когда нет внешнего таймера.

Сигнал окончания по-прежнему запускает Custom-Dialog-UI; прошивка не дублирует его.

Проверка на устройстве: создайте длинный таймер, затем короткий на той же колонке.
Кольцо должно показывать короткий; удалите его — должен появиться длинный.
Поставьте последний таймер на паузу и убедитесь, что кольцо перестало уменьшаться.
Таймер другой колонки не должен менять кольцо этой.
